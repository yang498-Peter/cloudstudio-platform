# 2026-04-19

- 用户反馈 `web-uploader/start-local.command` 启动不了。
- 复现结果：
  - `start-local.command` 原始失败点是 `cannot create temp file for here document: No space left on device`。
  - 当前磁盘只剩约 `113 MiB` 可用空间，`/System/Volumes/Data` 容量接近 100%。
  - `web-uploader` 目录内较大的数据目录包括：`pointclouds` 约 `7.0G`、`uploads` 约 `4.6G`、`projects` 约 `2.4G`。
- 已做修复：
  - 将 `start-local.command` 中的 Python 运行时检查从 heredoc 改成 `python -c`，避免低空间下因为 bash 临时文件失败而直接退出。
  - 调整 `start-local.command` 运行时优先级为 `node` 优先、`bun` 兜底。
  - 将 `setup-local.sh` 的默认 JS 运行时也调整为 `node` 优先，并把 Python 校验改成 `python -c`。
- 验证结果：
  - `.venv` 中 Python 依赖检查可正常通过。
  - `env PYTHON_BIN=\"$PWD/.venv/bin/python\" PYTHON3_BIN=python3 PORT=8090 node server.js` 可正常启动服务。
  - `curl -I http://127.0.0.1:8090/viewer` 返回 `HTTP/1.1 200 OK`。
- 仍需注意：
  - 机器剩余磁盘空间太低，虽然脚本已不再因 heredoc 立即崩溃，但后续安装依赖、导出、上传、缓存写入仍可能继续失败。
- 已新增长期维护文档：
  - `/Users/yangqi/.openclaw/workspace/potree-local/cloudstudio-server/CloudStudio_优化执行计划与维护记录.md`
  - 用于固定优化方向、已做操作、下一步任务、改动文件状态和踩坑记录，后续维护应以该文档为主线更新。
- 本地数据打开失败排查：
  - 用户前端看到的是泛化错误 `Point cloud conversion failed`。
  - 运行时抓到的真实服务端错误是 `ENOSPC: no space left on device, open '.../uploads/1776529055423_BEL-JOEL.zip'`。
  - 这说明至少最近一次失败不是 `PotreeConverter` 缺失，而是上传/写入阶段被磁盘空间打断。
  - 已在 `server.js` 中补充：
    - `ENOSPC` 统一翻译成 `NO_SPACE_LEFT` / “磁盘空间不足，无法继续写入上传文件或转换产物”。
    - 全局 Express error middleware，把 `multer`/上传阶段的未捕获异常也统一转为 JSON 返回。
  - 当前磁盘空间后来恢复到约 `5.7Gi` 可用。
