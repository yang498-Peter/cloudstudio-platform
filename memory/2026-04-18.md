# 2026-04-18

- 用户要求阅读代码库，了解软件整体功能与当前情况，重点关注坐标系、坐标转换以及相关算法路径区域。
- 代码库梳理结论：
  - `web-uploader` 是主业务应用，核心仍是 `viewer.html` + `server.js`，前端 feature 只是逐步抽离的壳层。
  - 坐标链主路径：`geo_info.csv`（ECEF 原点 + 四元数）→ `localToECEF` → `ECEF -> sourceGeodetic` → `proj4/pyproj` 到目标 CRS → 手动平移/旋转/尺度改正。
  - 浏览器快速路径只适用于 WGS84-like source geodetic 且不依赖复杂 server grid；否则前端会走 `/api/crs/transform` 调 Python `transform_coords.py`。
  - grid 文件通过 `grid_probe.py` 分类为 `nadgrids` / `geoidgrids` / `grids`；水平格网有机会浏览器侧处理，垂直/通用格网强依赖原生 PROJ。
  - 多项目场景对齐不依赖用户选定 CRS，而是基于各项目 `geo_info` 的 ECEF 原点换算到锚点项目局部坐标。
  - 坐标消费端主要是 measurement、capture、scanner-info、terrain、hover status、export-las；minimap 始终走 WGS84 地图路径，不走当前目标 CRS。
  - 当前风险：CRS 逻辑分散在 JS 与 Python 双实现中，`viewer.html` 是坐标真核心，且 README 明确指出 CRS / grid 全链路缺少自动化覆盖。
- 环境修复：
  - `web-uploader/.venv` 中 `pyproj` 的 macOS 原生扩展可因签名策略导致 `ImportError: ... library load denied by system policy`。
  - 实际修复方法：对 `site-packages/pyproj` 下的 `.dylib`/`.so` 做 `codesign --force --sign -` 重新 ad-hoc 签名。
  - 已把该修复固化到 `web-uploader/setup-local.sh`，以后重建 `.venv` 时会自动重签名。
  - 顺手修复了 `scripts/grid_probe.py` 对相对路径不稳的问题，现在会先把输入路径 `resolve()` 成绝对路径。
