CloudStudio Product UX Audit

产品体验、交互设计与客户可用性升级建议

审计日期：2026-05-18。范围覆盖首页、上传发布链路、点云 viewer、3DGS / SuperSplat 链路、多语言、视觉体系、任务状态与客户交付工作流。本轮为只读审计，没有修改软件功能代码。

总览结论 产品化硬门槛 首页与上传 点云 Viewer 3DGS 链路 视觉与多语言 发现的 Bug / 风险 建议路线图

总览结论

CloudStudio 已经具备“上传、转换、打开、浏览、测量、导出、3DGS 发布”的完整雏形，但当前更像内部工程工具加演示平台。要面向真实客户，需要先补齐数据安全、任务可恢复、发布权限、删除保护，再做 viewer 交互收敛和视觉专业化。

3P0 产品化硬门槛：数据覆盖、权限、硬删除
11P1 高优先级体验/流程问题
18+P2/P3 可逐步优化项
5并行子代理分块审计：主页、viewer、3DGS、工作流、视觉多语言
核心判断：先不要继续堆新功能。下一阶段应该围绕“客户不会丢数据、不会看到别人的数据、任务失败能恢复、界面能解释自己在做什么”做 V1 产品化收口。

产品化硬门槛

这些问题不只是 UI 漂不漂亮，而是决定能不能正式给客户使用。

同名上传可能覆盖或删除已有点云

P0

影响 用户用默认文件名或重复项目名上传时，旧场景目录可能被清理，缺少冲突确认、版本化和回收站。这是客户数据丢失风险。

建议 上传前检测重名，默认生成唯一版本；提供“覆盖 / 另存为 / 取消”选择；至少先实现软删除和保留历史版本。

涉及 web-uploader/server.js 上传和转换输出目录逻辑。

缺少用户、组织、项目权限模型

P0

影响 首页会列出所有 Published Scenes，静态点云、3DGS、导出文件路径可直接访问。真实客户场景下会被理解为数据泄露风险。

建议 先做最小账号体系：登录、组织/项目归属、角色权限、viewer 分享 token；公开分享必须显式创建、可撤销、可过期。

涉及 /api/clouds、/pointclouds、/gaussians、/exports、首页项目列表。

删除是全局密码 + 硬删除，缺少审计与撤销

P0

影响 拿到管理员密码的人能删除任意场景；UI 只有一个删除按钮，客户无法知道会影响哪些源文件、分享链接、导出文件和项目目录。

建议 删除改成项目权限控制；要求输入场景名二次确认；展示将删除的资源清单；引入回收站、审计日志和恢复机制。

涉及 首页删除弹窗、DELETE /api/clouds/:name。

首页与上传体验

首页品牌感已经起来了，但“客户第一次来到底该上传还是打开 viewer”还不够直接。

首次上传路径被埋得太深

P1

表现 常见 720px 高度下首屏主要是品牌 hero，看不到上传表单；进入工作区后先看到 Published Scenes，上传模块默认折叠。

建议 未登录时可以保留品牌页；登录后首页应是项目工作台。空状态下默认展开上传模块，Published Scenes 空列表给“Upload your first scene”主 CTA。

上传折叠控件和模式选择重复

P2

表现 折叠态有格式 chips，展开后又有 tabs；折叠按钮是无文字箭头，语义不清。

建议 折叠态只显示一句格式摘要和一个明确的“展开上传表单”按钮；展开后只保留一套 segmented tabs，并自动聚焦文件选择。

首页主按钮层级不服务“上传发布”主任务

P2

表现 Header 和 hero 都把 Open Viewer 作为强主按钮，上传反而是次级。新用户可能先打开空 viewer。

建议 首页主 CTA 改为 Upload / Publish；Open Viewer 降为“打开最近项目”或“浏览已发布项目”。Clear Log 这类按钮降级为日志区小链接。

点云 Viewer 体验

Viewer 功能很强，但入口太多、状态太分散。客户会感觉像“很多按钮的工程台”，而不是一个成熟的测绘交付软件。

顶部 Toolbar 过载，横向滚动与长标签降低可用性

P1

表现 顶部同时放打开、导出、截图、导航、测量、体积、采集、DXF、裁剪、颜色等二十多个入口。

建议 Toolbar 收敛成 6-10 个高频动作：Open、Fit、Navigation mode、Measure、Clip/Edit、Display。低频功能放 Inspector 或菜单。

左右侧栏收起逻辑不统一

P1

表现 右侧 Inspector 有关闭和恢复按钮；左侧 Scene Manager 桌面端没有同等明确的收起按钮，移动端又是 drawer。

建议 统一为“固定侧栏 + 明确折叠按钮 + 折叠 rail + 同位置恢复按钮”；左右两边使用同一视觉和交互规则。

缺少三维坐标轴 / 方位指示

P1

表现 有 Top / Bottom / Left / Right 按钮，但视口里没有固定 XYZ triad、北向/上方向、当前投影状态。

建议 在 viewport 角落增加可交互三维坐标轴和 North / Up 指示；显示 Perspective / Orthographic、Orbit / Fly 当前模式。

CRS 设置分散且过于工程参数化

P1

表现 Appearance 有 Source Geographic CRS，Coordinate tab 又有目标 CRS、manual builder、grid 文件、PROJ/WKT。客户容易分不清显示、测量和导出的坐标基准。

建议 重构为 Coordinate Setup 向导：Source → Target → Grid / Geoid → Preview Point → Apply / Export。高级 PROJ 参数默认折叠。

状态反馈分散，缺少统一操作中心

P2

表现 状态栏、toast、tool hint、panel badge 各自显示一部分信息；长任务和工具模式没有统一的“当前正在做什么 / 下一步怎么做 / ESC 取消”。

建议 增加全局 operation banner 或 status center，统一显示当前工具、下一步动作、后台任务进度、失败恢复入口。

DXF、体积、裁剪等高级模块像独立产品堆在 Inspector 中

P2

表现 Inspector 里有 8 个 tab；DXF 同时包含 overlay import、绘制、floorplan、导出；体积模块有 scenario、surface、advanced、contours、history。

建议 按工作流合并：View、Measure、Edit、Coordinate、Data。体积改成 Boundary → Method → Compute → Report 的引导式流程；DXF 拆成 Import Overlay 与 Draw / Export Linework。

3DGS / SuperSplat 链路

3DGS 已能上传和打开，但产品语义需要更清楚：可临时浏览、正在优化、优化完成，这三件事不能混在一起。

上传后“发布完成”表述过早

P1

表现 PLY 上传后先返回 direct-ready，再后台转 SOG，但首页会显示 3DGS browse ready 和 Open Viewer。

建议 状态拆成 Raw Ready、Optimizing、Optimized Ready、Optimization Failed；前端轮询转换 job，并在列表和结果卡同步显示。

转换进度和失败原因不够客户可读

P1

表现 后端已有 conversion job，但首页未充分展示阶段、队列、耗时、失败原因和重试入口。

建议 结果卡显示“上传完成、排队中、转换中、优化失败原因、建议操作”；失败时提供重试优化和下载诊断信息。

旋转策略仍偏硬编码

P1

表现 默认旋转依赖 rx/ry/rz 经验参数，不同数据源倒置或歪斜时需要人工改 manifest 或 URL。

建议 上传时提供 MVPS1 默认、无旋转、自定义、预览校正四种选项；把最终旋转写入资产 manifest，主页按钮始终打开正确方向。

分享链路缺少产品面

P2

表现 用户只能复制 Open Viewer 后的长 URL；/3dgs/:asset 会跳到内部 SuperSplat editor URL。

建议 保留短路径作为客户可见地址；增加 Copy Link、访问权限、过期时间、只读模式、下载权限说明。

视觉、图标、多语言与无障碍

这一层不是锦上添花。客户会通过这些细节判断 CloudStudio 是内部 demo 还是正式测绘产品。

优先级 问题 建议
P1 emoji 大量作为菜单、状态、tab、场景树图标，和 toolbar SVG 混用。 统一为 SVG / icon set；emoji 从正式客户 UI 中移除，状态用图标组件 + 文案表达。
P1 i18n 仍依赖“原文扫描翻译”和含 emoji 的 key。 客户可见文本统一语义 key；动态 toast、title、aria、placeholder 都走同一个词表。
P1 div 菜单、tab、图标按钮缺少完整 ARIA 与键盘导航。 菜单和 tab 用标准 button / role pattern；icon-only 按钮增加 aria-label、aria-expanded、aria-pressed。
P2 德语、芬兰语、瑞典语等长文本会挤压 toolbar、tabs 和卡片。 工具栏移动端只显示图标；右侧 tab 可滚动或变下拉；关键按钮设置最小宽度和换行策略。
P2 首页是 Tersus 红色，viewer 仍是 Apple blue，颜色 token 分裂。 定义品牌色、操作色、状态色、分析色四类 token；viewer 逐步接入同一视觉系统。
P3 个人署名/角色出现在客户产品页和 viewer 顶部。 移动到 About / version info；客户界面用公司、产品、支持入口表达。

发现的 Bug / 风险记录

这些项在审计中被标记为“可能导致客户明显困惑或线上事故”的问题，建议进入 GitHub Issues。

等级 问题 验收标准
P0 同名上传覆盖数据。 重复名称上传必须出现冲突处理，不允许静默删除旧数据。
P1 首页 body[data-i18n-ready="0"] 会在 i18n 资源异常时造成白屏。 禁用 i18n JSON 或加载失败时，页面仍显示英文 fallback 和错误提示。
P1 Potree build runtime 属于被 gitignore 的运行时资产，部署漏同步会导致 viewer 空白。 部署脚本显式检查 /potree/build/potree/potree.js、potree.css、workers、resources 均存在，缺失则失败。
P2 viewer 打开坏链接或 metadata 失败缺少客户可读错误页。 404/403/metadata 解析失败时显示错误原因、返回首页、重新选择数据、复制诊断码。
P2 导出依赖原始 LAS/LAZ 是否仍存在，列表未标记“可导出/仅浏览”。 项目卡和导出弹窗明确显示可导出状态；无源文件时解释限制。

建议路线图

Phase 1 · Customer-safe V1

先保住数据与权限

  • 账号、组织、项目权限、分享 token。
  • 同名冲突处理、软删除、审计日志。
  • 上传/转换任务化，刷新后可恢复。
  • 部署 preflight 检查运行时资产和数据目录。
Phase 2 · Viewer UX

把 viewer 从工程台收敛成产品

  • Toolbar 缩减，入口职责重分配。
  • 左右侧栏统一折叠交互。
  • 增加 XYZ triad、视角状态、空状态。
  • CRS 改成向导式 Coordinate Setup。
Phase 3 · 3DGS Publishing

让 3DGS 能稳定交付链接

  • 区分 Raw / Optimizing / Optimized 状态。
  • 3DGS 旋转预设和预览校正。
  • 分享链接、权限、过期、只读模式。
  • SuperSplat 做 CloudStudio wrapper，不依赖隐藏编辑器 UI。
Phase 4 · Visual System

做成统一、专业、多语言友好的界面

  • 移除正式 UI 中的 emoji，统一 SVG 图标。
  • i18n 语义 key 化，建立术语表。
  • 统一 Tersus / CloudStudio 视觉 token。
  • 补齐 ARIA、键盘操作、长文本布局。
